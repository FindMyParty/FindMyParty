## Codebase Patterns
- Use ES modules (`"type": "module"` in package.json) — all imports use `import/export`
- Use `.gitkeep` files to preserve empty directories in git
- OpenTelemetry packages use `^0.214.0` (sdk-node, exporters) and `^0.72.0` (auto-instrumentations)
- Working directory for bash commands may change — always use absolute paths or `cd` explicitly
- Import env vars only from `src/config/env.js` — never use `process.env` directly elsewhere
- Domain entities use zod for validation — zod is a pure library, not infrastructure, so it's allowed in domain layer
- Entity pattern: `static create()` for new instances, `static fromPersistence()` for reconstruction from DB
- Use `Object.freeze` for enum-like constants (e.g., `ItemStatus`)
- Env validation uses `safeParse` + `process.exit(1)` pattern for clear error messages on boot
- Fastify v5 requires a config object for `logger`, not a pino instance — export `loggerConfig` from `shared/logger.js`
- Health route uses `dependencyCheckers` map for injectable liveness probes — keeps route decoupled from infra
- Tests use `server.inject()` for in-process HTTP testing — no need to actually listen on a port
- Use case unit tests use `vi.fn()` mocks for ports — NOT in-memory adapters (those are for integration tests)
- Port interfaces use marker classes with `throw new Error("Not implemented")` — JS substitute for abstract interfaces
- Port file naming: `[entity]-[type].port.js` (e.g., `item-use-case.port.js`, `item-repository.port.js`)
- Use case file naming: `[entity].use-case.js` — class name is `[Entity]UseCase`
- Use cases receive dependencies via constructor injection: `{ itemRepository, eventPublisher }`
- Use cases import `NotFoundError` from shared/errors.js for not-found checks — this is the only shared import allowed
- In-memory adapters store data as JSON (via `toJSON()`) and reconstruct via `fromPersistence()` — mirrors real DB serialization
- In-memory adapter naming: `in-memory-[entity].repository.js`
- In-memory event publisher naming: `in-memory-event.publisher.js` — stores events as `{ routingKey, payload, publishedAt }` array
- Event publisher exposes `events` getter (returns copy) and `getByRoutingKey(key)` for test assertions
- Application service naming: `[entity].service.js` — class name is `[Entity]Service`
- Application services receive use cases via constructor injection: `{ itemUseCase }`
- Routes receive `itemService` (not `itemUseCase`) — routes never touch domain entities directly
- `buildServer()` accepts `itemService` option — wires it into route plugins automatically
- OTel SDK must be initialized before any other imports that need instrumentation — `initTelemetry()` is the entry point
- PrometheusExporter with `preventServerStart: true` + `reply.hijack()` serves metrics through Fastify without starting a separate server
- Sentry is optional — `initSentry()` no-ops gracefully when DSN is falsy
- Observability files live in `src/observability/` (not `src/shared/`) — separate concern from shared utilities
- Metrics route uses `reply.hijack()` to hand off to the Prometheus exporter's native HTTP handler
- Boot sequence: OTel init → env validation (on import) → connect DB → connect MQ → wire deps → start server → register shutdown handlers
- Graceful shutdown order: close HTTP server → flush telemetry → process.exit(0)
